
## Permissions

- Sample output of `ls -l` is as shown below.
```
[root@symphony-dev-cluster1 ~]# ls -l
-rw-------.  1 root root       1465 May 28  2024 anaconda-ks.cfg
-rw-r--r--   1 root root     179028 Aug  5 00:05 api.symphony-dev-cluster1.fyre.ibm.com.log
-rw-r--r--   1 root root       1390 May 16  2025 bash_profile
drwxr-xr-x   2 root root       4096 Jan 27  2025 cluster_setup
```
- The Permission section has 10 characters.
  - The first character represents type.
    - Type can be regular file(-), directory(d) or symbolic link(|)
  - The remaining 9 characters contains 3 groups.
    - The first group represents current user permissions for read(r), write(w) and execute(x).
    - The second group represents group permissions for read, write and execute.
    - The third group represents permissions to others for read, write and execute.
- There are permission caterogies of users that read, write and execution permissions can be 
  applied.
  - `u` -> User
  - `g` -> Group
  - `o` -> Others
  - `a` -> All
## Groups

- Every user in a linux system belongs to atleast one group called their primary group.
- An user can belong to multiple groups.
- Groups are used to organize users.
- The `groups` command displays user groups.
  - `id -Gn` also displays user group information.
```
[root@symphony-dev-cluster1 ~]# groups
root
[root@symphony-dev-cluster1 ~]# groups clusteradmin
clusteradmin : clusteradmin
[root@symphony-dev-cluster1 ~]# su clusteradmin
[clusteradmin@symphony-dev-cluster1 root]$ groups
clusteradmin
[clusteradmin@symphony-dev-cluster1 root]$ id -Gn
clusteradmin
```

## Changing permissions
- Permissions are also called modes, that's why changing permissions command is `chmod`.
```
Item    Meaning
chmod   Change mode command
ugoa    User category user, group, other and all
+-=     Add, Subtract or set permissions
rwx     Read, Write and Execute
```
- Here is an example of adding permission.
```
[clusteradmin@symphony-dev-cluster1 ~]$ ls -l
total 0
-rw-rw-r-- 1 clusteradmin clusteradmin 0 Jan 11 04:24 sales.data
[clusteradmin@symphony-dev-cluster1 ~]$ chmod o+w sales.data
[clusteradmin@symphony-dev-cluster1 ~]$ ls -l
total 0
-rw-rw-rw- 1 clusteradmin clusteradmin 0 Jan 11 04:24 sales.data
```
- Here is an example of removing permission.
```
[clusteradmin@symphony-dev-cluster1 ~]$ chmod o-w sales.data
[clusteradmin@symphony-dev-cluster1 ~]$ ls -l
total 0
-rw-rw-r-- 1 clusteradmin clusteradmin 0 Jan 11 04:24 sales.data
```
- Two permissions can be applied at a time. For ex, `chmod g+wx sales.data`.
- To set permissions for morethan one user category, seperate them with comma as in `chmod u+rwx,g-x sales.data`.
- To set all users read permission `chmod a=r sales.data`.
```
[clusteradmin@symphony-dev-cluster1 ~]$ chmod a=r sales.data
[clusteradmin@symphony-dev-cluster1 ~]$ ls -l
total 0
-r--r--r-- 1 clusteradmin clusteradmin 0 Jan 11 04:24 sales.data
```
- To remove all permissions leave blank as in `chmod o= sales.data`.
### Numeric based permissions
- The following table describes permissions applied for an user category.
```
Octal   Binary  String  Description
0       0       ---     No permission
1       1       --x     Execute permission
2       10      -w-     Write Permission
3       11      -wx     Write and Execute Permissions
4       100     r--     Read Permission
5       101     r-x     Read and Execute Permissions
6       110     rw-     Read and Write Permission
7       111     rwx     Read,Write and Execute Permission
```
- The ordering of user categories should be strictly followed. It means `user` followed by `group` followed by `others`.
- Here are the most commonly used permissions
```
Symbolic        Octal
-rwx------      700
-rwxr-xr-x      755
-rw-rw-r--      664
-rw-rw----      660
-rw-r--r--      644
```

## Working with groups
- To add a new group user the command `groupadd`. For ex, to add sales group use `groupadd sales`.
- To add user to a group use `usermod` command. For ex, `usermod -aG sales clusteradmin`.
  - `a` is for appending group, instead of removing existing group.
- When a file is created, its group is set to the user's primary group.
- `groups` command will list all the groups for an user.
- To change the group of a file `chgrp groupname filename` command.
- To assign permissions to a group use `chgrp g+rwx filename`.
  - For ex, to assign write permssions for the group to a file `chgrp g+x sales.data`. 
```
[clusteradmin@symphony-dev-cluster1 ~]$ groups
clusteradmin sales
[clusteradmin@symphony-dev-cluster1 ~]$ ls -l
total 0
-r--r--r-- 1 clusteradmin clusteradmin 0 Jan 11 04:24 sales.data
[clusteradmin@symphony-dev-cluster1 ~]$ chgrp sales sales.data
[clusteradmin@symphony-dev-cluster1 ~]$ ls -l
total 0
-r--r--r-- 1 clusteradmin sales 0 Jan 11 04:24 sales.data
[clusteradmin@symphony-dev-cluster1 ~]$ chmod g+w sales.data
[clusteradmin@symphony-dev-cluster1 ~]$ ls -l
total 0
-r--rw-r-- 1 clusteradmin sales 0 Jan 11 04:24 sales.data
```

### Directory permissions revisited.

- Permissions on a directory can affect the files in the directory.
- If the file permissions are correct, start checking directory permissions until root directory to verify if all permissions are correct.

### File creation mask
- File creation mask determines default permissions.
- If no masks were used, then the default permissions would be
  - `777` for directories
  - `666` for files
- File creation masks are typically set by system administrators to set some defaults. These can be overridden per user basis by using `umask` command.
- Usage of umask is `umask [-S] [mode]`
  - sets the file creation mask to mode if given.
  - use -S for symbolic notation.
- `umask` does the opposite of `chmod`. For ex, if `chmod 777` gives all permissions `umask 777` removes all permissions.
```
                        Directory       File
Base Permission         777             666
Subtract Umask         -022            -022
Creation permission     755             644

Base Permission         777             666
Subtract Umask         -002            -002
Creation permission     775             664

# Negative permissions become no permission as below
Base Permission         777             666
Subtract Umask         -007            -007
Creation permission     770             660
```    
- The common umask modes are 
  - 022
  - 002
  - 077
  - 007
- Here are all the resulting permissions created with all 8 umask permutations.
```
Octal   Binary  Dir permissions File Permissions
0       0       rwx             rw-
1       1       rw-             rw-
2      10       r-x             r--
3      11       r--             r--
4      100      -wx             -w-
5      101      -w-             -w-
6      110      --x             ---
7      111      ---             ---
```
- There are special modes with `umask` and `chmod` that contains 4 octal numbers.
  - `umask` 0022 is same as 022.
  - `chmod` 0644 is same as 644.
- Here is an example of `umask` displayed with 4 characters.
```
[clusteradmin@symphony-dev-cluster1 ~]$ mkdir testumask
[clusteradmin@symphony-dev-cluster1 ~]$ umask
0002
[clusteradmin@symphony-dev-cluster1 ~]$ umask -S
u=rwx,g=rwx,o=rx
```
- Working with umask
```
[clusteradmin@symphony-dev-cluster1 ~]$ mkdir a-dir
[clusteradmin@symphony-dev-cluster1 ~]$ touch a-file
[clusteradmin@symphony-dev-cluster1 ~]$ ls -l
total 0
drwxrwxr-x 2 clusteradmin clusteradmin 6 Jan 12 09:09 a-dir
-rw-rw-r-- 1 clusteradmin clusteradmin 0 Jan 12 09:09 a-file
[clusteradmin@symphony-dev-cluster1 ~]$ rmdir a-dir
[clusteradmin@symphony-dev-cluster1 ~]$ rm a-file
```
